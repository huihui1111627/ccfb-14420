# 古树名木普查 · R* 树空间索引

一座城市几万棵挂牌古树的通用空间索引：树木记着坐标、树冠多边形和巡查记录，
巡查员查身边 100 米内的树，规划部门查施工红线压到的树冠。索引本身是一个
**维度可配置（2 维 / 3 维）的 R\* 树**，全部逻辑只写一遍，2D 与“坐标 + 巡查日期”
的 3D 盒子共用同一套插入、分裂、删除和查询代码。

```
go run ./cmd/serve                 # 打开 http://127.0.0.1:8420/ 看索引结构
go run ./cmd/verify                # 4.5 万棵树 · 26 万次操作的全量对拍
go test ./...                      # 单元测试与小型对拍
```

## 一、索引实现（internal/rtree）

| 需求 | 实现 |
| --- | --- |
| 插入选子树：上面几层按面积增量，叶子上一层改按重叠增量 | `chooseSubtree`：`level > 1` 用面积增量（相同时比面积），`level == 1` 用重叠增量，再比面积增量、面积 |
| 节点溢出先不分裂；同一层一次插入只强制重插入一次，挑离中心最远的一部分 | `tryReinsert` + `insertCtx.reinserted[level]`：按 max(0.3M) 取中心距最远的条目，在本层重新插入；重插入后的递归插入不再对同层重插入 |
| 分裂：按各轴周长和选轴，再在该轴按重叠最小选分裂位置，重叠相同比面积 | `split`：两种排序 × 每条轴算全部合法两组的周长和选轴；在选中轴的分布上按两组 MBR 重叠面积最小定位，平局比总面积 |
| 删除后节点不足半满：整个节点拆掉，条目按原层重新插回 | `DeleteFirst` → `condense`：低于 `MinEntries` 的节点整块摘下（连同祖先连锁），收集 `(条目, 原层)`，最后逐个 `insertEntry(..., level)`；根只剩一个孩子时降层 |
| 批量建树用坐标排序切片的打包方式，并与逐条插入对比 | `BulkLoad`：STR（Sort-Tile-Recursive），每层按剩余轴数把节点总数开方得到 slab 数、逐轴排序切片递归到叶子容量，父层对子节点 MBR 再跑同一套切片；页面和验证器都给出树高、节点数、填充率、重叠面积对比 |
| 最近 k 棵 / 按距离递增一直取 | `KNN` 用 `container/heap` 按到 MBR 的最小距离出队，取满 k 即停；`KNNIterator` 每次 `Next()` 续跑优先队列，可按需一直取，并用 `LowerBound()` 暴露“尚未探索部分的最小可能距离” |
| 树冠多边形，索引存外接矩形，查询先过矩形再精确判多边形 | `Record.Crown` + `Record.MBR`；`CrownsIntersecting`（矩形红线）、`CrownsIntersectingPolygon`（多边形红线）、`TreesWithin`（巡查半径）都是索引矩形粗筛 + 多边形精判 |
| 维度可配，加巡查日期成为 3 维外接盒 | `geom.Rect` 是 D 维数组；`rtree.Config.Dim` 决定维数；`forest.DateAxis` 把毫秒时间映射到与米可比的数量级（1 天 = 40 个索引单位），三维树的插入/分裂/删除/查询与二维完全同一段代码 |

一些实现细节：

- **条目统一用 `Bounds()`**：内部条目的范围取自子节点 MBR，叶子条目取自自身矩形。
  重插入内部条目时 `Rect` 是空的，早期版本会因此算错，测试覆盖了这一点。
- **3D 日期轴量纲**：直接把 Unix 毫秒当第三轴会让空间划分失效（同一查询访问节点数是 2D 的 38 倍）。
  按“1 天 = 40 单位”缩放后，6 年巡查窗约 8.8 万单位，与 4 万米的城区同量级；
  90 天时间切片的查询平均只访问约 19 个节点。
- **面积统计**：每层覆盖面积用扫描线求矩形并集；重叠同时给两个口径——层内**任意两节点**相交面积之和，
  以及只统计**同父兄弟**的重叠（R* 分裂启发式直接压的量）。3D 树的条目在时间轴上是零厚度薄片，
  3D 并集体积恒为 0，因此 3D 统计按树冠投影（前两轴）计算并在报告里标记 `projected`。
- **平面查询始终走平面索引**：3D 模式下 `Survey.Space2D` 维护同一批树的树冠 MBR 索引。
  树冠相交与最近邻都是平面语义，若走 3D 索引会把日期差算进“距离”并错误剪枝；验证器与页面都覆盖了这一点。
- **并发**：树的写操作不加锁，由上层（`viz.Server` 的 RWMutex）保证串行；读查询可并发。

## 二、页面（cmd/serve）

`http://127.0.0.1:8420/` 三个标签页，纯单文件 HTML + Canvas，无外部依赖：

- **查询**：地图上拖框（按住 Shift）或右键取最近 k 棵 / Shift+右键查半径内古树。
  橙框是本次查询**实际访问到的节点**，配色按层区分；HUD 显示命中数、访问节点数 / 总节点数、
  检查的叶子条目数、索引与暴力遍历耗时，以及逐层访问数。真·3D 模式下可加巡查日期区间。
- **分层与重叠**：逐层节点数、覆盖面积（并集）、重叠面积（层内两两相交之和）、重/覆比，
  点击某层可在图上只看该层；还有本次查询逐层访问和叶子填充统计。
- **建树与对比**：逐条插入 vs STR 打包的树高/节点/填充率/重叠面积；一键跑强制重插入开/关的
  同批查询对比；在当前查询框附近插入或删除，直接观察树高与结构变化。

接口：`/api/meta`、`/api/tree`、`/api/records`、`/api/query`、`/api/knn`、`/api/within`、
`/api/redline`、`/api/ab`、`/api/mutate`、`/api/dim`。

## 三、验证（cmd/verify）

`internal/verify` 生成按城区成团分布的古树（55 个片区、少量郊区散生树、树冠为 5–9 边凸多边形），
随机穿插执行 26 万次操作，**每一次都与暴力遍历全部古树的结果比对**：

| 操作 | 占比 | 比对方式 |
| --- | --- | --- |
| 2D 范围查询（100 m / 公园 / 片区 / 极小框） | 24% | 命中 id 集合完全一致 |
| 3D 范围查询（含 90 天巡查期切片） | 21% | 同上，第三轴带日期窗口 |
| 最近 k 棵（k=1..25） | 12% | 按 (树冠距离, id) 排序逐位一致 |
| 递增最近邻（取前 1..40） | 8% | 同上 + 距离单调不减 |
| 施工红线（矩形） | 10% | 树冠多边形精确相交结果一致 |
| 施工红线（旋转矩形多边形） | 7% | 同上 |
| 删除 | 12% | 删除后树仍满足 R* 结构不变量 |
| 插入（含删后重插、挪位重测） | 6% | — |

另外还有：二维/三维树的 R\* 结构不变量校验（父子层级、半满、平衡、MBR 一致、记录数、重复 id）、
STR 与逐条插入在同批查询上的结果比对、强制重插入开/关的 A/B 统计。

最近一次完整运行（`go run ./cmd/verify`，本机 Apple Silicon）：

```

duration 122s
ops    delete 31224  insert 15597  knn 31561  stream 20950
       range2d 62432  range3d 54302  redline_rect 25681  redline_polygon 18253

STR bulk load:           height 3, 3057 nodes, leaf fill 0.983 vs 0.748,
                         avg 36.2 vs 48.5 nodes/query on the same 400 queries
forced reinsertion:      avg nodes/query 57.4 (on) vs 59.9 (off)
                         splits 4087 vs 4382, reinsertion 7227 ops / 36135 entries
                         total overlap 1.88e9 vs 3.15e9 m² (on/off)
3D (date axis):          height 4, avg 105 nodes/query (mix of all-time and
                         90-day-slice queries; a 90-day slice alone is ~19)
```

强制重插入的收益随数据分布浮动（多次运行 4%–9% 更少访问），但整树重叠面积稳定更低；
开关两种建树的同批查询答案完全一致。

`go test ./...` 里有一个 2500 棵树 / 1.2 万次操作的同款对拍，几十秒内跑完，作为回归测试。
